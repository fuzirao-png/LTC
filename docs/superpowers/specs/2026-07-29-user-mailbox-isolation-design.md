# 一名销售一个邮箱：隔离设计

## 目标

让每名销售绑定且仅绑定一个启用邮箱。平台登录密码与邮箱 SMTP/IMAP 密码完全分离；发送、收件、提醒、邮件历史和客户首页均按销售用户隔离。

## 数据模型

- 新建 `ltc.user_mailbox`，以 `user_id` 唯一约束保证一名销售一个邮箱。
- 保存邮箱地址、SMTP/IMAP 主机端口、SSL、启用状态和加密后的邮箱凭据。
- 加密主密钥仅来自本机或部署环境变量 `LTC_MAIL_CREDENTIAL_KEY`，不进入数据库或 Git。
- `ltc.email_message` 增加 `sales_user_id`，标记邮件归属销售。

## 权限与数据流

- 发件接口必须认证，后端从访问令牌取得 `user_id`，忽略前端传入的用户标识。
- SMTP 客户端仅解析当前用户启用的邮箱；缺少绑定时明确报错，不回退到其他销售或全局邮箱。
- 每个 IMAP 轮询器携带邮箱所属 `user_id`，入站邮件、提醒和历史均写入该归属。
- 销售只能读取自己的提醒、历史和已认领客户；战略账号保留全量管理视图。

## 本地初始化

- 保留 `li.ming`，地区 `EA`、层级 `MA`，绑定用户指定的运营邮箱。
- 新建 `zong.lin`，地区 `NA`、层级 `MA`，绑定用户指定的运营邮箱。
- 两个邮箱密码通过本地一次性初始化脚本/环境变量加密写入，不写入迁移、源码、日志或 Git。

## 验收

1. 两名销售分别登录后，发件人地址与各自绑定邮箱一致。
2. 两个邮箱互发带唯一主题的邮件，两个收件轮询器均能入库。
3. 每名销售只能看到自己邮箱收到的提醒和自己的邮件历史。
4. 销售首页仅展示本人已认领客户；战略账号仍可查看全量。
