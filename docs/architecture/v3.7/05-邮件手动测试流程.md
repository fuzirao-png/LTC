> 目的：方便用真实邮箱手动验证收信、发信、入库和回信链路是否顺畅。

## 3. 手动测试收信

### 3.1 触发一次立即轮询

```powershell
$response = Invoke-RestMethod -Method Post http://127.0.0.1:8790/api/inbound-mail/poll-now
$response
```

重点看：

- `createdCount`：这次新写入了几封收信
- `notifications`：收到了哪些邮件
- `errors`：有没有轮询失败

### 3.2 查看数据库是否入库

```sql
select email_id, direction, status, from_address, subject, received_at, created_at, message_id_header
from ltc.email_message
where direction = 'inbound'
order by created_at desc
limit 20;
```

如果收信成功，会看到 `direction = inbound`、`status = received` 的记录。

---

## 4. 手动测试发信

### 4.1 调接口发一封测试邮件

```powershell
Invoke-RestMethod -Method Post `
  -Uri http://127.0.0.1:8790/api/email/send `
  -ContentType "application/json" `
  -Body (@{
    customerName = "Postgres Test Company"
    recipientName = "Test Buyer"
    recipientEmail = "your-test-box@example.com"
    subject = "DB smoke test"
    body = "Hello from LTC"
  } | ConvertTo-Json)
```

### 4.2 看发信结果

返回里通常会有：

- `success`
- `message`
- `record`

### 4.3 查发信入库

```sql
select email_id, direction, status, from_address, intended_to_address, delivered_to_address, subject, sent_at, created_at
from ltc.email_message
where direction = 'outbound'
order by created_at desc
limit 20;
```

### 4.4 查投递尝试

```sql
select delivery_attempt_id, email_id, attempt_no, provider_code, status, started_at, accepted_at, completed_at
from ltc.email_delivery_attempt
order by started_at desc
limit 20;
```

## 5. 手动测试回信

1. 先用平台发一封邮件到真实邮箱。
2. 在真实邮箱里直接点“回复”。
3. 等 IMAP 轮询，或者手动再触发一次：

```powershell
Invoke-RestMethod -Method Post http://127.0.0.1:8790/api/inbound-mail/poll-now
```

4. 再查入库：

```sql
select email_id, direction, status, from_address, subject, received_at, parent_email_id, thread_key
from ltc.email_message
order by created_at desc
limit 20;
```

如果是同一线程，回信一般会带上 `parent_email_id` 和 `thread_key`。

---

## 6. 常见排错

### 6.1 `createdCount = 0`

说明这次轮询没有找到新邮件。先确认：

- 邮箱里真的有新邮件
- 监控邮箱在 `mailbox_monitor` 里是启用状态
- 服务日志里没有 `poll failed`

### 6.2 发信成功但数据库没记录

先看接口返回值，再查：

```sql
select * from ltc.email_message order by created_at desc limit 20;
select * from ltc.email_delivery_attempt order by started_at desc limit 20;
```

### 6.3 收到邮件但时间不对

通常是邮件头时间和入库时间不同。数据库里：

- `received_at` 更接近邮件实际收到的时间
- `created_at` 是系统写库时间

---

## 7. 一句话版流程

看监控邮箱 -> 发一封测试邮件 -> 触发轮询 -> 查 `email_message` 和 `email_delivery_attempt` -> 再用真实邮箱回一封 -> 再轮询一次看回信是否入库。
