# 项目架构分块与迁移路线

本文按 `LTC_Agent_MVP技术脚手架_字段_API_SkillMemory开发基线_v1.0.md`
梳理当前项目结构，并记录客户运营迁移边界。

## 1. 当前运行结构

```text
前端浏览器
  -> 8787 Node 同源服务
     -> 静态 index.html
     -> 邮件/会议旧接口
     -> 代理客户分析 Agent
  -> 8765 线索收集 Agent
  -> 8000 会议分析服务
  -> 8790 客户运营 Agent（新迁移目标）
```

## 2. 模块分块

### 前端展示层

- 根目录 `index.html`
- `runtime-config.js`
- `src/` 和 `LTC_Agent/apps/ltc_frontend/` 为工程化/历史前端代码

当前主入口仍是 `http://127.0.0.1:8787/`。

### 线索收集 Agent

- 目录：`LTC_Agent/clue_agent`
- 端口：`8765`
- 职责：对话式线索收集、Exa/Apify 等外部搜索、真实线索表格返回

### 客户分析 Agent

- 目录：`customer-analysis-agent`
- 职责：客户画像、ICP/报告、销售指引
- 当前由 `mail-api.js` 代理 `/api/analysis/*` 和 `/internal/events/*`

### 会议分析服务

- 目录：`meeting-analysis-service`
- 端口：`8000`
- 职责：上传音视频后的 ASR 转写和摘要
- 被客户运营旧服务和新服务调用

### 客户运营 Agent

- 目录：`customer-operation-agent`
- 建议端口：`8790`
- 职责：邮件生成/发送、回复识别、会议上传/轮询/历史、跟进任务、客户阶段流转

新目录已经按 MVP 基线拆为：

```text
app/
  api/            请求入口
  core/           配置
  schemas/        字段契约
  services/       业务编排
  skills/         AI 能力
  memory/         上下文拼装
  integrations/   外部服务：LLM、Resend、会议分析
  prompts/        Prompt 文件化
  workflows/      后续 LangGraph/状态流转位置
```

### 旧 Node 同源服务

- 目录：`邮件自动发送_Windows/邮件自动发送/demo/mail-api.js`
- 端口：`8787`
- 当前仍承担：
  - 静态前端服务
  - 现有前端邮件/会议接口
  - 客户分析 Agent 代理
  - 客户分配/客户运营部分 mock 接口

短期不删除，避免影响当前可演示链路。

## 3. 客户运营迁移状态

已迁入 `customer-operation-agent`：

- `GET /api/email/history`
- `POST /api/email/generate`
- `POST /api/email/send`
- `GET /api/customers/operation/email/history`
- `POST /api/customers/operation/email/generate`
- `POST /api/customers/operation/email/send`
- `GET /api/meeting/history`
- `POST /api/meeting/upload`
- `GET /api/meeting/job`
- `GET /api/meeting/audio`
- `POST /api/meeting/delete`
- 旧 JSON 历史数据适配
- 调用 `meeting-analysis-service` 的客户端
- LLM 邮件生成 Skill
- Resend 邮件发送 Integration

暂留 `mail-api.js`：

- 静态前端服务
- `/api/analysis/*` 代理
- `/internal/events/*` 代理
- 客户分配 mock
- 客户分析 mock
- 当前前端仍在使用的同源接口实现

## 4. 推荐后续落地顺序

1. 先并行启动 `8790`，确认客户运营新接口能读写旧 JSON 数据。
2. 在 `runtime-config.js` 增加客户运营 API Base，可灰度切到 `8790`。
3. 前端邮件弹窗从 `/api/email/*` 切到 `8790`。
4. 前端会议弹窗从 `/api/meeting/*` 切到 `8790`。
5. 确认连续演示无问题后，从 `mail-api.js` 删除邮件/会议业务逻辑，只保留静态服务和代理。
6. 最后再考虑把客户分配 mock、客户运营主列表真实化。

## 5. 服务器上传建议

当前不要一次性大搬根目录。建议保留：

- `index.html`
- `runtime-config.js`
- `LTC_Agent/`
- `customer-analysis-agent/`
- `customer-operation-agent/`
- `meeting-analysis-service/`
- `邮件自动发送_Windows/`
- `docs/`
- `data/`
- 启动脚本

需要重点忽略：

- `.env`
- `.env.local`
- `node_modules/`
- `.venv*/`
- `__pycache__/`
- 上传音频和本地生成历史数据，除非演示需要
