Lead growth

线索 Skill：从找到公司到识别成交对象

线索增长
Q

企业信息搜索词生成

将行业、区域、场景、ICP 与历史结果转成多组检索计划。

得到：提高召回率，搜索过程可重放
E

搜索结果可信源筛选

按官网、监管、媒体、聚合站点及内容时效评估证据。

得到：减少错误 ICP 与虚假企业字段
ID

LinkedIn URL 标准化

规范公司页、个人页和 slug，合并域名与名称别名。

得到：降低重复率，提高 Apify 命中率
DM

Decision Maker Finder

识别决策人、影响者、技术负责人和采购角色。

得到：线索从公司级进入联系人级
S

Signal 公司动态监控

监控融资、招聘、扩张、产品上线和管理层变化。

得到：按采购时机触发销售任务
ICP

Niche Signal Discovery

从赢单、输单和人工标签中发现新的细分 ICP 信号。

得到：评分模型随真实业务结果演进
接入：Lead Intelligence
复用：Exa / Apify / Evidence
主要指标：有效候选率 · 重复率 · 字段可信度

Engineering governance

工程 Skill：让业务能力稳定、可查、可评

工程治理
IO

Instructor

将 LLM 输出绑定到 Pydantic Schema，并自动处理校验失败。

得到：减少 JSON 解析失败与字段漂移
LF

Langfuse

追踪 Prompt、模型、Token、延迟、版本和调用链。

得到：知道哪个 Skill 为什么成功或失败

得到：上线前量化质量，防止版本退化
APM

串联 API、Worker、Provider 与 LLM 的异常和性能信息。

得到：快速定位失败发生在哪一层

PostHog

得到：用真实使用行为衡量产品价值
API

从 LTC OpenAPI 合约生成前端类型和 API Client。

得到：减少前后端字段不一致和手写代码

复用：OpenAPI / Job Attempt / Trace ID
主要指标：Schema 失败率 · 回归通过率 · MTTR

边界原则

现在可以做

保存接受、修改、拒绝和错误原因；建立 50–100 条黄金样本。

随后接入

DeepEval、Langfuse、Sentry/OpenLLMetry 等评测与观测工具。

暂不自动化

ICP 自学习、话术自优化、成单预测，在标签不足时不直接上线。

Technology choices

保留现有底座，限制高成本扩张

取舍

继续复用

  • FastAPI + Pydantic：接口与结构化输出边界
  • PostgreSQL：业务事实、Job、Evidence、Audit
  • Vue 3：人工确认与反馈采集界面
  • OpenAI-compatible Adapter：LLM / ASR 可替换
  • Exa + Apify：搜索和联系人 Provider
  • SMTP / IMAP：现有邮件闭环

当前暂缓

  • Supabase、Twenty CRM、CordysCRM：重复底座
  • Flowable、Casbin：当前流程与权限复杂度不足
  • Composio、Calendar/LinkedIn MCP：OAuth 与副作用面过大
  • Qdrant、pgvector、AnythingLLM：先定义长期记忆场景
  • WhisperX / Pyannote：需评估 GPU、隐私和运维
  • GenericAgent / PydanticAI：避免重写应用服务层
Idea validation path

从产品假设到技术验证，可分三步推进

验证路径

验证能力可组合

概念验证
  • 明确用户、任务、触发点和期望输出
  • 用现有模块拼出最小可运行流程
  • 定义 Manifest、输入输出与 Owner
  • 识别数据、权限和外部 Provider 依赖

验证用户愿意使用

场景实验
  • 选择一个真实销售流程做灰度
  • 保留人工确认与结果证据
  • 观察节省时间、采用率和结果质量
  • 采集接受、修改、拒绝及原因

判断是否值得产品化

规模判断
  • 形成黄金样本和固定评测集
  • 核算成本、延迟和维护复杂度
  • 评估跨客户复用与配置边界
  • 决定产品化、继续实验或停止
Brainstorm prompts

脑暴会要回答：LTC 下一步值得试什么

不急于确定一次做多少；先从四条机会线中形成具体的用户场景、需求假设和最小实验。

1

哪个用户问题最值得解决

2

哪些能力能组合成新功能

3
