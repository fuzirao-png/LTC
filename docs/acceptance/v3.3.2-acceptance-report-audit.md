## 报告之外确认并修复的问题

1. Lead Intelligence 的四个读取端点缺少认证依赖，未登录请求可能在鉴权前访问数据库。
2. 搜索任务创建端点未强制 Strategic 身份和 `Idempotency-Key`，前端三个入口也没有全部传递该请求头。
3. 客户运营页面的“发送邮件”按钮没有调用真实发送 API。
4. Worker 虽然声明了 `lead.search_pipeline.v1`，但当前构建没有可执行的 Worker 用例；默认部署已切换为 API inline 执行，Worker 默认只消费已接通的 `crm` 队列，避免任务接受后静默失败。
5. IMAP 轮询原先在 API 事件循环中直接执行同步处理，导致 LLM 协程未 await 和请求阻塞；现移到线程执行，并补轮询回归测试。
6. 入站邮件通知、邮件详情和已读接口原先没有认证依赖；邮箱轮询和监控配置还可被非经营角色调用。现要求登录，监控和主动轮询限制 Strategic，通知读取对已登录角色开放。
7. Web 长时间打开后 access token 过期不会自动刷新，导致页面仍显示登录但业务请求全部 401；现由共享 HTTP 客户端单飞刷新并重试原请求，刷新失败才触发退出。
8. HTML-only 入站邮件原先会把 style/div 标记作为正文预览；现解析为纯文本，避免后续新邮件污染客户运营列表。

## 复验建议

1. 使用符合 OpenAPI 的请求体和请求头，不以故意缺字段得到的 422/502 判定前端不匹配。
2. 先创建分析任务并等待任务终态，再检查报告列表和五段内容。
3. 对生产性能问题至少记录 30 次样本、p50/p95、数据量和 PostgreSQL 查询计划。
4. 对数据为空的项先区分“接口失败”和“测试夹具未准备”，不要用伪造数据消除 null/unknown。
5. Deferred 能力只有在正式架构文档更新后才能进入实现和验收。
